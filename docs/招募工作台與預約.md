# 招募工作台、邀約預填與面談時段

版本：`3.0.0-candidate.7`，lichongfu 的候選版，不是老師正式 v3。
主要入口：LINE 首頁第三張卡「招募工作台」「預約面談」，或整合結果中的同名按鈕。

## 工作台在哪裡

工作台就在同一個 LINE 聊天室內，沒有另一個網站，也不是人資自己的 Google Drive。
同一份職缺的候選資料按 LINE 訪客雜湊分開存取。一般訪客不能讀別人的清單；資料實際存在 bot 主人執行 GAS 的私人 Drive，檔案擁有者仍可讀取。
候選資料隨目前職缺一起到期，最長 24 小時；到期後不可查閱，後續使用時清理。最多五位候選人。換職缺或刪除職缺會移除目前工作台資料，已送出的訊息無法收回。

## 需求熱圖與多人比較

1. 先貼完整職缺，確認條件。主流程開始比對後，可點「人資：候選比較」；人資不必代替候選人回答三題。
2. 點「新增候選人」，依格式貼上已獲授權的工作相關履歷文字，總長最多 4000 字：

```text
候選人代號：候選 A
履歷：
使用 Python 開發 API 工具，負責錯誤處理與驗證。
專案成果、本人負責部分及其他工作經驗……
```

3. 候選人姓名可改用代號。貼入文字會交給 Gemini 找與職缺相關的引用，不寫入原 Google Doc 或履歷索引，不另做圖片 OCR。
4. 「加入此 bot 履歷」可沿用已比對的公開證據；此履歷更新後，需要重新比對並更新該候選資料。
5. 「需求熱圖」以列呈現職缺條件、欄呈現候選人。綠色「原文」表示找到可核對引文；黃色「待查」表示待確認；灰色「排除」表示不納入評估。
6. 「資料覆蓋排序」先依必要條件有原文的筆數，再依全部有效條件覆蓋率排列。同分保留加入順序，不以姓名或其他背景排序。
7. 「候選清單」可查看逐項引文、提供的履歷文字、人工決定，或確認刪除候選資料。

只使用同一份職缺的同一組條件比較。每項引文必須對到提供文字的片段 ID，並逐字存在於該片段；格式或引文失敗不會加入一筆空白候選資料。
程式排除年齡、性別、婚姻、宗教等無關條件，並在送模型前移除標示此類資料及聯絡個資的部分行。此規則可能連同同一行其他資訊一起排除，因此提供者應貼乾淨的工作相關資料。

## 百分比和人工決定

證據覆蓋率＝有可核對引文的有效條件數／有效條件總數，四捨五入為整數百分比。無有效條件時不計算。
此數字只描述履歷資料支持情況，不是能力分數、符合機率、績效預測或錄取建議。沒有引文不代表不具備能力，原文存在也不保證符合條件或真實性。

系統不自動評能力分數、不自動錄取或淘汰。人資可選「邀請面談／待補充／不續辦／錄取（人工記錄）」，填 4～300 字的工作相關理由，預覽後再確認。
人工理由不交給 AI，也不會自動通知候選人。更新此 bot 的來源證據後，先前人工決定保留為前次紀錄，需要重新審核。

## 邀約自動預填

主流程結果點「留下邀約」後，自動帶入職稱、條件對照摘要，以及最多兩項待確認問題。摘要會精簡至原表單長度限制，明確標為節錄；完整職缺另隨邀約保存。
接著只需填公司／稱呼、回覆方式及時間，不重問已帶入的職缺內容。
送出前可預覽，點「修改職缺與問題」修改預填文字。三題原始回答不會默默寄出。
確認後，邀約與原職缺保存於私人收件匣；Email 通知附原職缺，LINE 通知包含摘要。通知成功僅表示平台接受，不代表已讀。

## 本人設定可面談時段

需先設定 `OWNER_LINE_USER_ID` 為本人 LINE user ID。只有該帳號可管理時段。

1. 輸入「管理面談時段」，或在「預約面談」中點「管理時段」。
2. 點「新增時段」，輸入：

```text
2026-11-15 14:00 / 2026-11-15 14:30
```

請換成當下未來的日期。使用台北時間，開始時間限未來 90 天內，時長 15～180 分鐘。最多三十個未來開放時段。
發布時會拒絕與既有開放或已預訂時段重疊。關閉時段需確認；已預訂者須先取消預約才能關閉。

## 人資預約與防止重複預訂

1. 點首頁／結果的「預約面談」，或邀約表單中的「選擇面談時段」。
2. 選擇後暫留五分鐘，其他訪客的可用清單不再顯示該時段。
3. 完成邀約並「確認送出」時，在同一把指令碼鎖內重新檢查時段、保存預約及邀約，再發送通知。任何一方已占用、時段被關閉或暫留過期，都不會顯示成功，也不會送出通知。
4. 五分鐘內沒完成確認，其他訪客後續查詢時會釋放暫留。輸入取消、回首頁、重新填寫或更換時段，也會釋放該草稿的暫留。
5. 「我的預約」可查詢自己的紀錄；本人可看全部預約。取消需再次確認，取消後釋放時段，系統不自動寄取消通知，需自行告知對方。
6. 有有效預約的邀約不能直接從收件匣刪除，須先取消預約。

此防撞只涵蓋同一個 bot 的這份共享時段表，不讀寫 Google Calendar，也不處理外部其他平台的預約衝突。
預約保存及占用時段代表登記保留，面談細節仍需雙方確認。排程資料在結束三十天後，於後續排程操作時清理；邀約仍依原收件匣由本人管理。
實作使用既有 [GAS LockService](https://developers.google.com/apps-script/reference/lock/lock-service)，沒有新增 Calendar 權限。

## 介面調整與驗收

首頁按鈕區統一高度、間距及底部對齊。「貼職缺」為綠色主要按鈕，其餘使用綠色文字連結，移除整片灰色堆疊與首頁內重複的回首頁按鈕。
三題面試演練與人資比較共用原職缺，但人資工作台不把人資輸入當作候選人本人已驗證的回答。

本機測試包含分檔與單檔：多人原文核對、資料隔離、百分比與排序規則、人工確認、來源過期、邀約預填及修改、暫留、兩人爭同時段、重複提交、存檔失敗不預訂／不通知、取消與重疊時段。
尚未使用真實 LINE/Gemini 完成端到端驗收，也未量測真實速度、費用或選才效果。

更新方式：完整取代新 `dist/Code.gs`、儲存、原部署選「建立新版本」。`checkDeployment` 兩個版本應同為 `3.0.0-candidate.7` 且 `status=ready`。
