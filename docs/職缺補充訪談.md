# v3 候選：職缺補充訪談

本功能是 lichongfu 的 `3.0.0-candidate.2` 候選實作，不是老師發布的正式 v3。
相關討論：https://github.com/canlgz/ResumeRAGbot/discussions/1

## 已實作的範圍

人資貼職缺 → 選一項原文條件 → 確認送出 → 本人收到 LINE 通知 → 依序回答三題 → 本人預覽確認分享 → 人資主動查看摘要及面試追問。

第一版採固定、透明的三題框架：相關經驗與本人貢獻、困難與處理結果、工作期待與學習支持。
第一題帶入人資選定的原文條件；正式面試追問帶入對應回答的前 100 字作提示。
本流程不呼叫 Gemini，不自動分析整份職缺、不判定必要或加分條件，也不自動查找或核對履歷證據。
人資仍可使用原有履歷問答與作品功能查證。三題回答只標示為本人補充陳述，不當成已驗證事實或能力分數。

## 設定與使用

1. 保留原 Doc、金鑰與指令碼屬性。確認 `OWNER_LINE_USER_ID` 是本頻道本人 Your user ID，且本人已加入 bot 好友。
2. 完成本機檢查後，把新產生的 `dist/Code.gs` 完整取代 GAS 單檔程式；manifest 與 `gas/appsscript.json` 核對。
3. 更新原部署到新版本，沿用原 `/exec` 網址，再執行 `checkDeployment`。
4. 用不同於本人通知帳號的人資 LINE 帳號，點首頁第三張卡的「貼職缺，詢問三題」，或輸入「職缺對照」，貼最多 4000 字的職缺文字。只有網址不受理，超長內容不截斷。
5. 從原文複製一項重點條件（最多 200 字），確認職缺及資料用途後送出。
6. 本人收到編號通知後，輸入「待回答職缺」，選擇編號，查看原職缺，再開始回答。每題最多 800 字，可略過或暫停。第三題完成後可重答全部三題，再確認分享。
7. 人資輸入「我的職缺」查看進度與分享結果。不主動向人資推播，避免保存人資原始 LINE ID。超過十筆時可輸入 `jm:view:需求編號` 開啟較早的需求。

「首頁」會離開填寫；本人已填的答案暫存，人資未送出草稿則清除。
本人或提出需求的人資可刪除需求，其他訪客無法存取。取消已送出需求後不會補發通知。
邀約表單正在填寫時優先完成邀約；完成或取消後再開啟職缺流程。

## 保存、通知與限制

- 未送出的職缺草稿存於私人 Drive，30 分鐘有效；送出需求及回答七天有效。到期後拒絕查閱，於下次進入本流程時清理；未安裝背景清理排程。
- 與現有作品管理共用本人的私人 Drive JSON；職缺與回答不寫進 Doc 或履歷索引、不送模型。
- 只保存人資身分的專案雜湊。本人通知使用原有 `OWNER_LINE_USER_ID`。
- LINE 推播的 `sent` 只表示平台接受，不代表已送達或已讀。通知失敗仍保留需求；本人可查清單。不自動重送結果不明的推播。
- 同時最多 30 筆需求與 30 份草稿；本人一次回答一份，切換另一份時暫停原份。
- 分享後內容凍結。需要補充時另建需求；刪除無法收回已傳送、已讀或對方自行保存的訊息。
- 保留原 GAS 秘密 Webhook 網址的既有限制；GAS 入口仍無法驗證 LINE 簽章，請參考 README 的使用範圍。

## 驗證狀態

本機模擬涵蓋分檔與單檔完整流程、三題順序、事件重送、分享前隱私、跨訪客權限、略過、重答、長輸入、舊按鈕、暫停與切換、刪除、過期、通知失敗及既有邀約優先。
本機測試不會發出真實通知。

GAS 更新部署、手機版面、真實通知與 LINE 實測均尚未確認。
提交 GitHub 不會自動更新 GAS。
