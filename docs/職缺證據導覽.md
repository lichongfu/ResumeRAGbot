# 職缺面試流程：同一份職缺完成三題訪談

版本：`3.0.0-candidate.6`。這是 lichongfu 的候選實作，不是老師的正式 v3。
相關討論：https://github.com/canlgz/ResumeRAGbot/discussions/1

## 重新設計的主流程

貼職缺 → 確認條件 → AI 比對證據、依序問三題 → 確認回答 → 查看同一份整合結果與正式面試追問 → 自行決定是否邀約。

三題固定包含在主流程中；題目由 Gemini 根據本次職缺、履歷證據及缺口生成，並非固定題型。
所有步驟使用同一份職缺、同一個私人狀態。不需要切換人資／應徵者角色、不需重新貼職缺，也不要求本人通知設定。

## LINE 操作

1. 輸入「首頁」，第一張卡提供「看履歷」「貼職缺」「聯繫邀約」。
2. 點「貼職缺」，貼上職稱、工作內容及條件，20～4000 字。只有職稱或網址時會要求補充，不會假裝已收到完整職缺。
3. AI 摘錄最多六項原文條件。確認後才比對；可在「調整條件」移除不想比對的項目，至少保留一項。
4. 系統一次查詢多項條件，完成後直接顯示第一題，不再每比對一項就要求按繼續。三題從資訊缺口、本人貢獻與驗證方式等面向安排。
5. 每次直接回答一題，最多 800 字；可略過、稍後繼續，或先查看相關證據。每題回答先保存在私人資料中，此時尚未交給 Gemini 生成後續追問。
6. 三題結束後預覽回答，可修改任一題而保留另外兩題。按「確認，整理面試結果」後，回答才送至 Gemini 產生三個正式面試深入追問。
7. 結果頁固定提供「證據與作品」「三題回答」「面試追問」「完整準備單」「留下邀約」「職缺設定」。完整準備單可在 LINE 長按複製，尚無 PDF 匯出。

回首頁、輸入「取消」或點「稍後繼續」都是暫停，保留職缺與回答。從首頁「我的職缺與訪談」返回原步驟。
已經貼過職缺時，再點「貼職缺」會先問要繼續或更換，不會清空資料。
更換職缺時先貼新內容，再確認取代；確認前原職缺與回答保留。「職缺設定」中的刪除也需再次確認。

測試職缺：

```text
職缺：AI工程師
工作內容：使用 Python 開發 AI 應用，串接 API。
必要條件：具備 Python 專案經驗。
加分條件：使用過 Google Apps Script。
```

## 資料的來源與界線

- 公開證據：每項只接受自己檢索片段中的 ID 與逐字引文。圖片只代表可見內容，不證明作者、本人貢獻、技術、上線或成效。
- 條件類型：由原文明確標題辨識必要、加分；未辨識或有歧義則列為未指定，不擅自提升為必要。最多六項不代表涵蓋全部職缺。
- 缺少引文：標為待確認，未記載不代表不具備能力。不顯示能力分數或符合率。
- 三題回答：明確標為「本次對話填寫者補充（未驗證本人）」。只有與已設定 `OWNER_LINE_USER_ID` 相同的帳號才標為「已設定的履歷本人帳號補充」，仍須查證內容。
- 正式追問：在填寫者確認三題回答後，由 Gemini 根據回答與公開證據生成。不能將回答自動升為已驗證的履歷事實。
- API 或引用錯誤：保留目前步驟及已存回答並提供重試，不誤標為資料不足或已完成。

對話填寫者應依自身用途回答：可由本人做面試準備，也可在面談時記錄候選人補充。系統不從答案內容推斷填寫者身分，不自動轉交另一位人資。

## 舊版職缺與舊按鈕

candidate.5 已貼上的職缺沿用原資料與 ID，按「我的職缺與訪談」或舊「待回答職缺」即可回到同一份資料。既有條件可直接進入新版比對與三題訪談，不必重貼。
舊的角色切換、三題訪談與清單入口會引導回新版主流程，不再啟動另一套角色或需求清單。
若職缺只存在更早的舊版訪談資料中，可在無目前職缺時選「沿用舊版職缺」，驗證存取權後匯入文字；舊紀錄保留，不自動把舊回答當成新證據。

## 邀約

「留下邀約」接回原有邀約表單，開表單不代表送出；仍須填寫並確認，才保存及依設定寄信／推播。
若已有未完成邀約，會繼續該份，不能由重按結果按鈕覆蓋。正在填邀約時先完成或取消，再回職缺流程。
本版本尚未自動預填職缺到邀約，也沒有面談時段保留、需求熱圖或多人排序。

## 保存與更新

每位訪客保存一份目前職缺，以專案及 Doc 綁定的雜湊隔離，存於本人的私人 Drive。最多三十位訪客；24 小時後禁止查閱，後續操作時清理，沒有背景清理排程。
職缺不寫回 Doc、待補充問題或履歷索引；不重新 OCR 或重建索引。新的比對使用一次批次查詢向量與一次生成；條件摘錄與回答確認後的追問各另有一次生成。真實延遲與費用尚未量測。
開始分析、生成後與顯示證據時均核對來源指紋。履歷更新時暫停提供舊證據，同步後可重新比對；前一組回答保存在「查看前次回答」，不自動用於新分析。
租約及事件紀錄防止慢請求、重送或舊按鈕覆蓋目前職缺、吃掉下一題或重複生成。

更新 GAS：完整取代 `dist/Code.gs`、核對 manifest、儲存，再編輯原 Web App 部署並選「建立新版本」，沿用原 `/exec` 網址。
執行 `checkDeployment`，編輯器與正式部署應同為 `3.0.0-candidate.6` 且 `status=ready`。Push 不會自動更新 GAS。
